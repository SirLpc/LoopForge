# WSL2 预热工作区设计

在这台 WSL2 的 Docker Desktop 中运行专用 Runner。两份 Unity 检出、运行位置和 Git 缓存位于一个专用 Docker 本地 Linux 卷。保留 D 盘原件。预热工作区沿用原子移动、独占租约、远端授权和零整目录快照。现有 Runner 继续提供已有会话和普通工作区，专用 Runner 使用自己的登记和状态。

Runner 启动时核对本机 Docker Desktop、自己的容器和实际挂载。任务、Git 帮助进程和受支持的工作区入口按租约挂载卷里的精确子路径。验证 Docker 请求中的子路径和解析出的卷身份。可写范围仅为当前工作区，受保护的 Git 对象和运行工具使用只读挂载。初始验证发现 Desktop 的绝对路径绑定可以指向别处，明确的卷子路径可以读取已知测试文件。

专用 Runner 通过租约接收仓库任务。无仓库的文本阶段也使用自己的 Docker 容器，只挂载该会话的目录。已租用仓库的对话仍通过租约接入，并挂载独立的会话目录。浏览器连接经验证的容器 ID。运行工具只允许来自专用工具目录。

归还前逐个核对运行中和已停止容器的卷挂载。无法归属的重叠写入或挂载会保留槽位。Runner 自己的卷挂载通过容器身份和本地独占状态验证。短期诊断容器使用同一 Docker 引擎的宿主 PID 视图，无网络、只读根文件系统，仅加进程检查所需的两个能力。现有基础流程仍要求完整宿主 PID 视图。可信 Docker 管理员只能维护排除调度的空闲槽位。

使用临时卷和经授权的测试仓库验证移入、执行、失败保留、归还和重新接管。再用用户的本机配置准备真实数据。保护现有 Runner 状态、源目录和项目权限。平台配置沿用现有入口。
