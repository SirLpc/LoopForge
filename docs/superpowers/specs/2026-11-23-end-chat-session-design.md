# 结束 Chat 会话并归还预热工作区

## 目标

用户可主动结束普通 Chat 会话，归还会话自己持有的预热槽位，并保留聊天记录、附件、产物和关联需求。结束后仍能从会话列表打开原会话查看历史。继续讨论时使用新会话。

## 方案选择

| 方案 | 取舍 |
| --- | --- |
| 结束后只读 | 用户选定。归还成功后保存结束状态。在原会话查看历史，在新会话继续讨论。 |
| 支持恢复会话 | 增加恢复入口和状态转换。恢复后可继续使用原会话，需要工作区时重新排队。 |

## 用户操作

普通个人和项目 Chat 会话沿用会话菜单及项目访问权限。菜单增加「结束会话」。确认框说明会停止当前回复、尝试归还预热工作区并保留记录。SOP 和定时任务会话沿用各自的生命周期。

提交后显示「正在结束」。当前回复已生成的内容按现有取消流程保存。结束期间暂停本地消息队列。成功后在原会话显示「已结束」，用简短提示替换输入区，隐藏编辑重发、重试及会话工作区操作。列表仍可打开该会话，置顶、重命名、归档和删除仍可用。

归还受阻时显示具体原因，例如未推送的改动、未关闭的终端或 Unity 项目锁。会话恢复可用，用户处理后可重试。多个工作区分次归还时，已确认的归还继续生效，其余工作区保留各自的租约状态。已归还的工作区可按现有流程重新领取，直到用户再次结束会话。

## 服务端和归还

- 通过助手会话入口发起结束请求。服务端在会话记录中保存处理状态和结束时间，旧记录默认处于可用状态。会话列表和详情都返回状态。归还在后台执行，刷新页面可继续查看进度与结果。
- 在会话行锁下登记结束操作，阻止其他标签页或实例同时启动回复，也阻止排队转向、编辑重发、待确认操作和工作区重新绑定。结束流程请求取消当前生成或预热排队，等待已接受的执行退出并完成记录收尾。开始新一轮和写入历史的服务端入口都按会话状态校验，结束前已接受的回复可以完成正常收尾。
- 仅对该会话自己打开的预热工作区复用现有归还流程，Runner 继续校验进程、Git 内容和产物。会话借用的 SOP 工作区仍由原 SOP 管理，普通检出的回收沿用原有机制。所有预热租约均已确认归还或取消后，校验原绑定与租约代次，记录会话结束时间并解除当前工作区绑定。产物和历史工作区的关联信息保留。
- 重复请求读取现有结果，同一会话只有一项有效的结束操作。后台处理有时限，服务重启后可重试，迟到的结果须核对同一次操作才能写入。归还失败保留会话内容与具体原因。删除会话继续使用现有删除流程。

## 验收

- 验证空闲会话、正在回复、等待预热槽位及普通无预热工作区的会话均可按规则结束，历史和已生成内容可读。
- 验证 Runner 拒绝归还、多个工作区部分归还、重复提交和服务中断后的重试，以及借用 SOP 工作区的生命周期。
- 验证并发发送与结束有明确顺序，结束后新的生成、编辑重发和工作区会话操作被服务端拒绝。刷新后显示同一状态，附件与关联记录仍可查看。
