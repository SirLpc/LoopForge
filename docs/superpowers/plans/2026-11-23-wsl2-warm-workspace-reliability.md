# WSL2 Warm Workspace Reliability Implementation Plan

> **For agentic workers** Use `superpowers:subagent-driven-development` or `superpowers:executing-plans` to execute each task. Use `superpowers:test-driven-development` for each regression.

**Goal** Make native WSL2 borrowing, exact restore, and return recover safely after Git failures, external edits, and Runner interruptions.

**Architecture** Keep the WSL2 bind mount and the existing lease generation fence. The Runner persists checked Git intent before changing a checkout. The control plane persists pending native return receipts alongside confirmed recovery refs, and the Runner rechecks local state before unmounting.

**Tech Stack** Go, Git, Git LFS, GORM, WSL2, and bubblewrap.

**Spec** `docs/superpowers/specs/2026-11-23-wsl2-warm-workspace-reliability-design.md`.

## Global Constraints

- Use the registered Windows checkout and preserve `.git`, `Library`, ignored files, and local-only commits. Keep the existing Runner mounts, owner gates, remote authorization, and lease generation checks.
- Keep implementation in the native Runner and warm-workspace files. `internal/domain/runner_workspace.go` carries two optional protocol fields. Use the existing GORM AutoMigrate for a nullable JSON field in `run_warm_workspace_refs`.
- Keep existing Docker pool behavior and its return wire data. Maintain compatibility with the native Runner's older journal and old return receipts.
- Use synthetic repositories, a local bare remote, and disposable slot roots. The Windows filesystem integration uses a dedicated temporary directory on D: and a private WSL mount namespace.

## Review Focus

- Staged changes or hidden tracked changes after a clean `git status` must block any destructive recovery. Task 1 tests byte and index verification.
- A same-size modified LFS file during checkout recovery must stay intact. Task 2 tests verified and modified LFS files of the same length.
- A newer local branch tip outside the authenticated namesake remote branch, or a ref changed while switching, must stay intact. Task 2 tests the guard and compare-and-swap.
- A delayed stale response after a replacement receipt with identical refs must preserve that replacement. Task 3 tests the receipt ID and workspace-use token fences.
- A partial return with an archived file already deleted and one mount absent must stay reserved through restart until local recheck. Task 4 tests a two-slot return, with both the unchanged and changed checkout cases.

## Running the checks

Use the Go toolchain specified in `go.mod`. The investigation used Go 1.26.11, Git LFS 3.7.1, and temporary bare remotes. Use `-count=1` for fresh results. On this WSL host, run tests that create mounts or listen on localhost outside the execution sandbox with the tool's approval flow. If the temporary filesystem is low on space, run Go tests with `-p 1 -ldflags='-s -w'` or set `GOTMPDIR` to a disposable directory on the Linux filesystem.

For WSL tests set `LOOPFORGE_TEST_NATIVE_MOUNTS=1` and set `LOOPFORGE_TEST_NATIVE_SLOT_PARENT` to a temporary directory on an actual Windows drive. Run the test process under `unshare --user --map-root-user --mount --propagation private --`. Keep the Runner state and cache for those tests on the Linux filesystem.

### Task 1 — Local verification of the original checkout

**Files** `internal/runner/warm_workspace_release.go`, `internal/runner/warm_workspace_lfs.go`, `internal/runner/warm_native_proof.go`, and `internal/runner/warm_native_proof_linux_test.go`.

**Interfaces** Extract `(*warmReturnTree).verifyLocal(ctx context.Context, slot warmWorkspaceSlot, cache string, repo domain.RunnerRepository, ref domain.WarmWorkspaceRef, lfsMode warmProofLFSMode) error`. Use `warmProofLFSFetch` for the existing authorized proof, `warmProofLFSCache` for an offline verification using protected objects, and `warmProofLFSContent` to compare the starting checkout's actual bytes against committed pointers and object IDs. Only the fetch mode uses the credential context for transfer. Verify the exact `HEAD` and attached branch in the native checkout. For return confirmation, `cache` and `repo` come from the frozen slot and its protected Git cache. The helper reads actual files from `w.checkout`. The `warmReturnTree` optional `artifactPrefix string` maps physically separate original paths back to the recorded owner-relative archive paths. Return `errWarmTreeChanged` for proven content or repository-state changes and propagate read or cancellation errors independently.

- [ ] **Write regression tests.** `TestWarmNativeLocalProofChecksBytesAndIndex` checks that a clean checkout passes, a tracked edit with `--assume-unchanged` and a staged edit both satisfy `errors.Is(err, errWarmTreeChanged)`, and a canceled operation satisfies `errors.Is(err, context.Canceled)`. `TestWarmNativeLocalProofUsesArchivedPaths` passes `artifactPrefix: "checkout"` with an original checkout outside `root` and asserts `proof.collected["checkout/result.txt"] == digest`. `TestWarmNativeLocalProofUsesOnlyCachedLFS` asserts missing protected objects cause an error without a network call, `errors.Is(err, errWarmTreeChanged)` is false for that cache error, and a hydrated file or intact pointer matching the manifest passes once the local object is available.
- [ ] **Run the new tests.** `go test -count=1 ./internal/runner -run '^TestWarmNativeLocalProof'`. Expect the missing verifier and classification to fail the new cases.
- [ ] **Implement the local proof.** Keep remote authorization in `(*warmReturnTree).verify`. Move the index, file, attribute, ignore and Library checks into `verifyLocal`. In the checkout verification path, use an isolated proof index and the protected object cache, with native proof alternates for the original objects. Use `prepareWarmLFSWithFetch` with an explicit `allowFetch bool` internally and keep `prepareWarmLFS` as the existing fetch-enabled wrapper. Extend the blob comparison below the current boolean test API so mismatches, failed file reads, and cancellation remain distinguishable. For recovery of the starting checkout, verify committed pointers and hydrated bytes from the original commit's manifest without requiring the starting revision to be published. For the target or return proof, require validated protected objects.
- [ ] **Verify.** `go test -count=1 ./internal/runner -run 'TestWarmNativeLocalProof|TestWarmWorkspaceRelease|TestWarmReturn|TestWarmNativeReturn|TestWarmWorkspaceLFSTransfers'` passes with the existing Docker test prerequisites respected.
- [ ] **Commit.** `git commit -m 'refactor: isolate byte verification for warm workspaces'` after staging the task files.

### Task 2 — Recover checkout intent and restore the exact branch safely

**Files** `internal/runner/warm_native_git.go`, new `internal/runner/warm_native_checkout.go`, `internal/runner/warm_workspace_access.go`, `internal/runner/warm_workspace_control.go`, `internal/runner/warm_workspace_state.go`, and `internal/runner/warm_native_linux_test.go`.

**Interfaces** Add `nativeWarmCheckoutIntent` with `SlotID string`, `Before, Target domain.WarmWorkspaceRef`, `BranchBefore, Baseline string`, and `Rewind bool`. Add `NativeCheckout *nativeWarmCheckoutIntent` to `warmWorkspaceAllocation` with `json:"nativeCheckout,omitempty"`. `prepareNativeWarmCheckout(ctx context.Context, checkout, cache string, slot warmWorkspaceSlot, repo domain.RunnerRepository, restore *domain.WarmWorkspaceRef, pending *nativeWarmCheckoutIntent, beforeWrite func(nativeWarmCheckoutIntent) error) (domain.WarmWorkspaceRef, error)` prepares or resumes exactly one repository. Provide `(*warmWorkspacePool).recoverNativeCheckoutForReturn(ctx context.Context, a warmWorkspaceAllocation, repos []domain.RunnerRepository) (warmWorkspaceAllocation, error)` for Task 4. Use Task 1's local content verification for all recovery decisions.

- [ ] **Write native lease regression tests.** `TestWarmNativeLeaseRestoresPublishedHistoricalBranch` returns commit A, advances the remote branch and slot to B, and reopens A. Assert `HEAD == A`, the active branch keeps its name, the remote is still B, and the original `Library/sentinel` has the same identity. Add a local-only commit, then attempt restore and assert `HEAD` and its reference are unchanged. Add a branch update during checkout and assert the recorded old tip cannot overwrite the newer tip. `TestWarmNativeLeaseRefreshesBaseline` asserts `.git/agentflow-baseline` equals B for the later ordinary lease, equals A on exact restore, and remains pinned within a generation when a later remote commit is fetched.
- [ ] **Write interruption tests.** `TestWarmNativeCheckoutResumesIntent` interrupts before Git writes, after checkout, and during LFS materialization. Assert the pending slot, old and new refs, and baseline survive reopening the pool, and retry produces the recorded target. Modify a hydrated file to different bytes of the same length, then assert recovery fails without changing it. Test already-prepared slots are kept in a two-repository lease. `TestWarmNativeCheckoutLegacyIntentNeedsInspection` asserts the legacy `PreparingGit` flag without `NativeCheckout` blocks recovery and preserves the files.
- [ ] **Run the new tests in WSL.** `go test -count=1 ./internal/runner -run 'TestWarmNative(LeaseRestoresPublishedHistoricalBranch|LeaseRefreshesBaseline|CheckoutResumesIntent|CheckoutLegacyIntentNeedsInspection)'` under the namespace described above. Expect the old-branch restore, baseline and retry assertions to fail before the fix.
- [ ] **Implement intent and branch handling.** Under the existing owner gate and journal mutex, persist intent before writing the branch, index or worktree. Pin the chosen target and baseline across retries. Check the target branch tip against the authenticated same-name remote ref before approving a historical rewind. For a rewind, detach at the exact target using the existing ignore-file protection, move the branch with `git update-ref` and the recorded old object ID, then reattach. During recovery accept a detached target only when the old or advanced branch ref is recorded and local proof matches. Record the prepared slot and clear intent together. Treat unchanged original content as safe to retry or cancel, and finish verified target state idempotently. Reject ambiguous state with a stage-specific reason. Use the existing busy or unavailable responses for a genuinely retryable interruption and editor contention, leaving the platform reservation in place.
- [ ] **Implement the baseline.** Resolve the exact target for historical or ordinary branch checkout. For an independent work branch resolve the current verified base in the protected cache and use the target as fallback. Import the required objects and atomically replace `.git/agentflow-baseline` before marking the slot prepared. Use the pinned SHA when retrying. Validate a real `.git` and regular baseline path and keep generic `gitwork.RecordBaseline` for the Docker pool.
- [ ] **Verify.** Re-run the focused namespace command plus `TestWarmNative` and `TestWarmWorkspace` from the Runner suite. Expect the new tests and existing warm-workspace tests to pass.
- [ ] **Commit.** Stage the task files and run `git commit -m 'fix: recover native warm checkout intent'`.

### Task 3 — Fence pending native return receipts on the platform

**Files** `internal/domain/runner_workspace.go`, `internal/domain/warm_workspace.go`, new `internal/repo/warm_workspace_native_return.go`, `internal/repo/warm_workspace_refs.go`, `internal/repo/runner_warm_workspaces.go`, `internal/engine/warm_workspace_release.go`, `internal/repo/warm_workspace_refs_test.go`, and `internal/engine/warm_workspace_release_test.go`.

**Interfaces** Add `WarmWorkspaceReturnID string` with `json:"warmWorkspaceReturnId,omitempty"` to both Runner workspace request and response. Define `domain.WorkspaceErrorWarmReturnStale = "warm_return_stale"`. Use `nativeWarmReturnReceipt{Epoch, Generation uint64; ID string; Refs []domain.WarmWorkspaceRef}` stored as a nullable JSON `PendingNativeReturn` field on `warmWorkspaceRefRow`. Expose `(*RunsRepo).WarmWorkspaceReturnReceipt(l domain.WarmWorkspaceLease) (id string, found bool, err error)` with empty ID for an existing legacy receipt. Add `RecordNativeWarmWorkspaceReturn(l domain.WarmWorkspaceLease, token, id string, refs []domain.WarmWorkspaceRef, now time.Time) error`, `InvalidateNativeWarmWorkspaceReturn(l domain.WarmWorkspaceLease, token, id string, now time.Time) error`, and `ConfirmNativeWarmWorkspaceReturn(l domain.WarmWorkspaceLease, token, id string, now time.Time) error`. Keep the existing public legacy methods. The Runner implements the matching optional fields in Task 4.

- [ ] **Write repository tests.** `TestWarmNativeReturnReceiptKeepsConfirmedRefs` records a first confirmed return, stages a different native receipt, and asserts `WarmWorkspaceRefs` still yields the original. Verify invalidation restores `ready` when `ReadyGeneration == Generation`, and an unadmitted return preserves old refs. `TestWarmNativeReturnRejectsStaleReceipt` asserts an expired workspace-use token or stale lease cannot invalidate a receipt, and invalidating ID A leaves replacement ID B with identical refs intact. Exercise an old unplaced receipt with no ID and old confirmed refs. Assert a caller-provided ID on `warm_release_commit` is canonicalized to the persisted one and no commit is authorized without a matching durable record.
- [ ] **Write engine tests.** `TestWarmNativeReturnEngineRetriesDurableReceipt` stubs the control transport, loses one commit acknowledgment, then verifies the next call skips check, sends the same ID and finishes. `TestWarmNativeReturnEngineInvalidatesMatchingReceipt` returns `warm_return_stale` with the persisted ID, then checks original ownership, old refs, and that a later release runs check and commit with the new ID. Test a mismatched reply ID leaves the pending receipt intact.
- [ ] **Run the new tests.** `go test -count=1 ./internal/repo ./internal/engine -run '^TestWarmNativeReturn'`. The receipt and stale-reply assertions fail without the platform changes.
- [ ] **Implement persistence and wiring.** Serialize changes under the existing owner run lock, live workspace-use token, and the warm lease identity. Reuse the database clock policy for lease expiry. Apply native receipt writes, invalidation and acknowledgment only to the frozen native owner. A matching pending receipt authorizes a commit with the canonical ID and refs. Promote refs and update cleanup state in the acknowledgment transaction only for a generation that reached ready. Preserve last-confirmed refs on staging, invalidation, and unadmitted return. Accept legacy native receipts on the old wire format, using the current lease, token and persisted legacy receipt to fence stale invalidation. Leave the legacy Docker `RecordWarmWorkspaceRefs` path intact. The engine passes or validates the receipt ID and uses the existing retry path when the reply is missing, mismatched or transient.
- [ ] **Verify.** `go test -count=1 ./internal/repo ./internal/engine ./internal/httpapi -run 'Warm|TestRunnerWorkspace(NeverReplaysDeliveredRequest|WaitsForReconnect)'` passes.
- [ ] **Commit.** Stage the task files and run `git commit -m 'fix: fence native warm return receipts'`.

### Task 4 — Verify and finish native return at the Runner

**Files** `internal/runner/warm_native_return.go`, `internal/runner/warm_workspace_return_control.go`, `internal/runner/warm_workspace_release.go`, `internal/runner/warm_workspace_state.go`, `internal/runner/warm_workspace_pool.go`, `internal/runner/warm_native_return_linux_test.go`, and `docs/warm-workspace-wsl2.md`.

**Interfaces** Store `NativeReturn *nativeWarmReturnState` with `json:"nativeReturn,omitempty"` on `warmWorkspaceAllocation`. The state has `ID string` and `CleanupStarted, Invalidated bool`. Keep references and paths in `ReturnRefs`, `PreparedRefs` and `ReturnRemove`. A present invalidated state with empty ID represents an invalidated legacy proof. Add `(*warmWorkspacePool).commitNativeReturn(ctx context.Context, l domain.WarmWorkspaceLease, id string, refs []domain.WarmWorkspaceRef) error`, `(*warmWorkspacePool).verifyNativeReturn(ctx context.Context, a warmWorkspaceAllocation) error` and `errWarmReturnStale`. Use Task 1's local verifier, Task 2's preparation recovery, and Task 3's protocol fields.

- [ ] **Write Runner regressions.** `TestWarmNativeReturnRejectsChangeAfterProof` edits a tracked file through the original path after check, then asserts a stale response with matching ID, source bytes unchanged, and slot still reserved. Assert the same rejected ID is recognized after restart and cannot commit a later proof. Repeat for an index change and a new unarchived file. `TestWarmNativeReturnLegacyReceiptRechecksFiles` loads pre-upgrade proofs and checks stale and clean results. `TestWarmNativeReturnUnadmittedStillChecksPreparedSlots` proves a partially prepared lease with no platform refs, changes the prepared slot, and expects stale with original ownership. `TestWarmNativeReturnRecoversInterruptedGroup` uses two slots, an already archived and deleted file, and a deliberately interrupted unmount. Restart, assert both slots are still assigned, then retry. In a second case edit the already-unmounted original and assert both mounts are restored before reporting stale. `TestWarmNativeReturnRetriesReleasedAck` repeats the same release commit after the local journal already says released and asserts an idempotent ACK.
- [ ] **Run the regressions.** `go test -count=1 ./internal/runner -run '^TestWarmNativeReturn'` under the WSL namespace. Expect the post-proof edit, proof replay and restart assertions to fail without the Runner changes.
- [ ] **Implement native return.** Resolve pending checkout intent under the owner gate before proof. Assign a receipt ID to each new native proof, including empty unadmitted proofs. Reuse cached remote authorization for commit-time revalidation. Use the registered slot path on restart and map it to the logical archive path. Verify all applicable HEADs, index state, tracked bytes, untracked paths, and original Unity locks. Distinguish invalid data from temporary occupancy, cancellations and I/O failures. Record cleanup intent before removing files and allow already-removed, previously verified archived paths when retrying. Use the existing release fence and journaled unmount. Retain a returning lease on restart until the next verification. On a stale proof restore any missing mounts, persist invalidation, and reopen local access for the original lease. Reply idempotently for a known stale or already released receipt.
- [ ] **Verify.** `go test -count=1 ./internal/runner -run 'TestWarmNative|TestWarmWorkspace'` under the WSL namespace passes.
- [ ] **Update the runbook.** Describe coordinated upgrade behavior and the Windows Unity maintenance sequence in `docs/warm-workspace-wsl2.md`, including waiting for the slot's return before opening it.
- [ ] **Commit.** Stage the task files and run `git commit -m 'fix: revalidate native warm workspaces before release'`.
